<threat_model>
Threats:
- Malicious import specifiers attempting path traversal (e.g. `import foo from '../../../../etc/passwd'`)
- Infinite loops during symlink traversal or circular relative path resolution
Mitigations:
- `PathResolver` validates that resolved paths stay strictly within `repoRoot` boundaries; paths resolving outside `repoRoot` are rejected with `null`
- Normalize paths with `node:path.resolve` and verify `resolved.startsWith(repoRoot)`
</threat_model>

Output: `SymbolIndex` class and `PathResolver` with comprehensive unit tests for TS/JS and Python.
</objective>

Implement `src/intelligence/resolver/path-resolver.ts`:
1. `PathResolver` class taking `{ repoRoot: string; tsconfigPaths?: Record<string, string[]>; workspaces?: string[] }`:
   - Method `resolve(fromFile: string, specifier: string): ResolvedImport`
   - If specifier starts with `./` or `../`:
     - Checks target relative path with extensions: `['.ts', '.tsx', '.js', '.jsx', '.py', '/index.ts', '/index.js', '/__init__.py']`
     - Validates path is within `repoRoot`
     - Returns `{ specifier, resolvedPath, isExternal: false, isWorkspace: false }`
   - If specifier matches `tsconfig.json` path alias (e.g. `@/*`):
     - Substitutes prefix and checks existing files in `repoRoot`
   - If specifier matches workspace package (e.g. `packages/*` or monorepo workspace package name):
     - Resolves to package source directory
     - Returns `{ specifier, resolvedPath, isExternal: false, isWorkspace: true, packageName }`
   - If bare module name (e.g. `'express'`, `'zod'`, `'pytest'`):
     - Returns `{ specifier, resolvedPath: null, isExternal: true, isWorkspace: false, packageName: specifier }`
2. Helper `createPathResolver(repoRoot: string): Promise<PathResolver>`: reads `tsconfig.json` paths and workspace configurations.
</action>
