<threat_model>
Threats:
- Hallucinated or maliciously injected finding fields (e.g. invalid severities, unexpected properties, arbitrary code objects).
- Path traversal in finding file paths (e.g. `../../etc/shadow`).
- Phantom findings attributing issues to non-existent files or out-of-bounds line numbers.
Mitigations:
- Zod schema enforces exact enum values for `severity` and `category` and strips unrecognized properties (`.strip()`).
- `groundFinding` validates paths against repository boundaries, rejecting paths with traversal (`..`) or files not found in repository/diff.
- Line numbers are verified positive and clamped to actual file lengths.
</threat_model>

<objective>
Implement compiled Zod schema validation, robust JSON extraction, and repository grounding for model outputs.

Purpose: Guarantee that raw LLM text is securely parsed, schema-validated, grounded in real code, and ready for senior-engineer critic processing without crashing or hallucinated file locations.
Output: Schema compilation module, robust JSON extractor, grounding validator, repair prompt formatter, and comprehensive tests.
</objective>
