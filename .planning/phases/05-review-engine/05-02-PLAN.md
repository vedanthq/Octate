<threat_model>
Threats:
- Malformed model responses / hallucinated findings: LLM Critic returning findings with non-existent file paths, phantom line numbers (> total lines), or empty/fabricated evidence.
- Prompt injection / evasion: Malicious diff comments attempting to trick the Critic into dropping valid security findings or approving backdoors.
- Unbounded memory consumption during deduplication: Adversarial diff producing hundreds of duplicate candidate findings leading to $O(N^2)$ cross-comparison memory bloat or event loop starvation.
Mitigations:
- D-05 / D-06: Stage 3A deterministic hard floor runs `groundFinding` verifying file existence on disk, ensuring `startLine <= totalLines`, requiring `evidence.length >= 1`, and enforcing `minConfidence >= 0.6` before calling the LLM Critic.
- D-07: LLM Critic output is validated against compiled Zod schema. If invalid or failing, 1 schema-repaired retry is attempted. If it still fails, the engine fails fast by throwing `ModelError` (exit code 4) rather than passing unverified findings to developers.
- D-09 / D-11: Deduplication indexes findings by normalized file path and sorts by line intervals, performing $O(N \log N)$ interval overlap matching. Evidence lists are capped strictly at 5 items to prevent unbounded memory growth.
</threat_model>

    1. Implement multi-factor duplicate matching criteria (D-09):
       - Condition 1 (Interval Overlap): Same file and `Math.max(a.startLine, b.startLine) <= Math.min(a.endLine, b.endLine)`.
       - Condition 2 (Symbol & Category): Same file, `a.category === b.category`, and identical enclosing AST symbol enclosing `startLine` (queried from `symbolIndex.getFileSymbols(file)` where `sym.range.startLine <= line && sym.range.endLine >= line`).
       - Condition 3 (Root-Cause Signature): Same file and normalized title match (strip non-alphanumeric, lowercase, collapse whitespace, canonicalize phrases e.g. "sql injection", "null pointer", "unhandled error").
    2. Implement cluster merging and attribute conflict resolution (D-10, D-11):
       - Severity escalation: map severities to ordinal numbers (`critical: 5, high: 4, medium: 3, low: 2, info: 1`). The merged finding takes the highest severity across the cluster.
       - Maximum confidence: merged finding takes `Math.max(...cluster.map(f => f.confidence))`.
       - Contributing reviewers: merged finding records `contributingReviewers = Array.from(new Set(cluster.map(f => f.reviewer)))`.
       - Representative selection: pick the title, message, and suggestedFix from the finding with highest confidence (tie-break by longest description length).
       - Evidence union & cap: union all evidence items across the cluster. Deduplicate identical evidence items by `${ev.file}:${ev.startLine}:${ev.endLine}`. Strictly cap the merged evidence list at the first 5 items (D-11).
       - Union unique `relatedFiles` and `relatedSymbols`.
    3. Implement two-phase deduplication entry points (D-12):
       - `preCriticDeduplicate(findings: ModelFinding[], symbolIndex?: SymbolIndex): ModelFinding[]`:
         Performs initial syntactic clustering on DAG output. Drops exact duplicates and overlapping spans to minimize prompt token footprint before `critic.v1`.
       - `postCriticConsolidate(findings: ModelFinding[], symbolIndex?: SymbolIndex): ModelFinding[]`:
         Performs final multi-factor consolidation pass on Critic output to resolve any remaining duplicate recommendations.
    4. Write comprehensive unit tests in `src/review/dedup.test.ts`:
       - Overlapping line ranges in same file are merged into one finding.
       - Disjoint line ranges in same file remain separate findings.
       - Same enclosing symbol with same category are merged.
       - Merging `high` and `critical` findings produces a `critical` finding with max confidence.
       - Merging findings from `structural` and `semantic` reviewers sets `contributingReviewers` to `['structural', 'semantic']`.
       - Merging 7 distinct evidence items produces exactly 5 evidence items.

       ```typescript
       export interface HardFloorParams {
         findings: ModelFinding[];
         repoRoot: string;
         minConfidence?: number;
         diff?: string;
         getFileLineCount?: (file: string) => Promise<number | null>;
       }
       ```
       - Grounding check via `groundFinding`: file exists, no path traversal (`..`), `startLine <= totalLines`. Reject ungrounded.
       - Evidence check: `finding.evidence.length >= 1`. Every surviving finding MUST have at least 1 verified direct evidence anchor (D-06). Findings with empty evidence `[]` are discarded.
       - Confidence floor: `finding.confidence >= (minConfidence ?? 0.6)`. Drop findings below threshold (D-06).
       - Concrete actionability check (D-08): `finding.suggestedFix` must be >= 15 characters and not generic placeholder (`"TODO"`, `"fix this"`, `"be careful"`, `"N/A"`).
       - Intentionality / mock filter (D-08): check `isDeliberateIntentOrMock`. If true, discard.
    2. Implement Stage 3B: LLM Critic Quality Gate (`executeCriticStage`):
       ```typescript
       export interface CriticParams {
         findings: ModelFinding[];
         repoRoot: string;
         diff: string;
         reviewContext: ReviewContext;
         diagnostics: Diagnostic[];
         model: ReviewModel;
         minConfidence?: number;
         signal?: AbortSignal;
       }

       export interface CriticResult {
         findings: ModelFinding[];
         criticInvoked: boolean;
         usage: ModelUsage;
       }
       ```
       - Step 1: Run `filterDeterministicHardFloor`.
       - Step 2: If 0 findings survive Stage 3A, **skip Critic LLM call completely** (return `{ findings: [], criticInvoked: false, usage: { promptTokens: 0, completionTokens: 0, totalTokens: 0 } }`).
       - Step 3: If candidate findings survive:
         - Build `ModelRequest` with role-specialized `reviewTask` identifying the Critic role and embedding candidate findings (e.g. `'Senior Staff Critic: review, filter, and curate candidate findings:\n' + JSON.stringify(candidateFindings)`), `diff`, `context: reviewContext.items`, and `diagnostics`.
         - Call `model.generate(criticRequest)`. Note that `model.generate` automatically validates findings internally before returning `ModelResponse.findings`.
       - Step 4: Failure Resilience & Quality Gate (D-07):
         - If `model.generate` fails or throws `ValidationError`: catch the error and attempt **one immediate retry** with repair instructions.
         - If retry also fails: **fail fast by throwing `ModelError` (exit code 4)** using `new ModelError('Critic quality gate failed to validate findings', { error: String(error) })`. Unverified or uncurated candidate findings must NEVER be presented to the user.
       - Step 5: Check `signal?.throwIfAborted()`.
    3. Write comprehensive unit tests in `src/review/critic.test.ts`:
       - Deterministic hard floor drops findings with confidence < 0.6.
       - Deterministic hard floor drops findings with empty evidence (`evidence: []`).
       - Deterministic hard floor drops findings with phantom line numbers beyond file length.
       - Deterministic hard floor drops findings with trivial `suggestedFix: "fix this"`.
       - Skips Critic LLM call when zero findings pass Stage 3A (verifies `model.generate` not called).
       - Successfully invokes Critic model when valid findings exist.
       - Retries once on invalid model response.
       - Throws `ModelError` (exit code 4) when Critic call fails after retry.
