<threat_model>
Threats:
- Critical vulnerability suppression / finding flooding: An attacker crafts a pull request with numerous trivial or noisy diffs designed to exceed `maxFindings` and push critical security vulnerabilities out of the report.
- Unhandled cancellation / resource leaks: In-flight model calls or background promise pool tasks continuing to consume API quota after user cancellation (`Ctrl+C`).
- Malformed configuration injection: Invalid or extreme configuration values in `octate.yaml` causing runtime NaN scores or infinite loops in ranking.
Mitigations:
- D-15 / ASVS L1: Critical-protected truncation partitions findings into `critical` and `non-critical`. Findings with `severity === 'critical'` are unconditionally preserved in the final output and are NEVER dropped, regardless of the `maxFindings` threshold.
- D-16: `ReviewEngine` checks `signal?.throwIfAborted()` at every pipeline stage boundary and passes `signal` to all underlying model calls.
- Zod schema validation on `ReviewConfigSchema` enforces strict numeric ranges: `minConfidence` in `[0, 1]`, `maxFindings` in `[1, 100]`. Composite scoring math clamps all metrics to `[0, 100]`.
</threat_model>
