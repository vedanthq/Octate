<threat_model>
Threats:
- T-07-01: Terminal escape sequence corruption & unrecovered cursor state on crashes/signals. When developer exits the interactive TUI via 'q' or Ctrl+C, the terminal must restore the primary buffer (`\x1b[?1049l`) and re-enable cursor visibility (`\x1b[?25h`) without leaving raw escape sequences on screen.
- T-07-05: CI pipeline hang on unhandled interactive TUI prompt. In automated CI environments (e.g. GitHub Actions, GitLab CI) or headless scripts, running `octate review` could freeze indefinitely if it attempts to launch the interactive TUI.
- T-07-06: Exit code mismatch between interactive dismissal and process exit. The exit code returned to the shell MUST match the real-time blocking count calculated at the moment of quitting: 1 if any unsuppressed blocking findings remain, 0 if clean or all blocking findings were suppressed in-session.

Mitigations:
- T-07-01 Mitigation: `InteractiveTuiRenderer` invokes `TerminalLifecycleManager.enter()` immediately upon starting review. A clean `try/finally` error trap in `runReview()` and `InteractiveTuiRenderer` guarantees `TerminalLifecycleManager.exit()` is unconditionally called if `useCase.execute()` throws or when Ink unmounts, restoring the primary buffer and cursor visibility.
- T-07-05 Mitigation: `src/commands/review.ts` invokes `shouldUseTui({ isTTY: process.stdout.isTTY, ci: Boolean(process.env.CI), term: process.env.TERM, noTui: options.tui === false, json: options.json, sarif: options.sarif, quiet: options.quiet, outputFile: options.output })`. If any check fails, format defaults to `'console'` (or requested automation format), preventing any TUI launch in CI.
- T-07-06 Mitigation: On session exit, `InteractiveTuiRenderer` calculates `finalBlockingCount` strictly against unsuppressed findings (`const activeFindings = result.findings.filter((f) => !finalSuppressedIds.has(f.id)); const finalBlockingCount = countBlockingFindings(activeFindings, threshold); process.exitCode = finalBlockingCount > 0 ? 1 : 0;`) and writes a concise 1-line summary to `process.stderr` per D-16.
</threat_model>
