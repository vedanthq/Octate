<threat_model>
Threats:
- T-07-02: Malicious diff ANSI injection & unescaped control characters in source code snippets. Untrusted repository files or commit messages could inject terminal clear/spoof sequences during interactive browsing.
- T-07-03: State machine desynchronization & blocking count bypass on finding suppression. Pressing 's' suppresses a finding; if the state reducer does not immutably filter active findings or cursor tracking desynchronizes from the flattened navigation items list, the developer could unintentionally suppress or display the wrong finding, leading to an unverified bypass of blocking findings policy.
- T-07-04: Terminal overflow, clipping, or crash on small terminal dimensions. When terminal width is under 100 columns or height is under 24 rows, rigid fixed-width layouts can crash Yoga/Ink or cause continuous text wrapping that corrupts the alternate screen buffer.
- T-07-06: Exit code mismatch between interactive dismissal and process exit. If a user suppresses all blocking findings in the interactive TUI, but the exit status calculation evaluates the unsuppressed findings array, the CLI exits with 1 despite user dismissal, or vice versa.

Mitigations:
- T-07-02 Mitigation: All file lines and diff text rendered through `CodeSnippet` and `DetailPane` pass through `highlightTokens` and `formatDiffLines` which sanitize raw control characters before rendering.
- T-07-03 Mitigation: `tuiStateReducer` is implemented as a 100% pure TypeScript reducer. `buildNavItems` flattens headers and findings deterministically; cursor movements clamp strictly to `[0, navItems.length - 1]`. All suppression operations work on immutable `ReadonlySet<string>` collections.
- T-07-04 Mitigation: `App` hooks `useStdout()` columns: when columns $\ge 100$, it renders a side-by-side horizontal split (navigator 38% width, detail pane flexGrow); when columns $< 100$, it automatically collapses to vertically stacked view. Long titles and message lines are truncated safely with standard ellipsis or bounded flexbox wrapping.
- T-07-06 Mitigation: `calculateActiveBlockingCount(state)` evaluates active findings dynamically (`state.findings.filter(f => !state.suppressedIds.has(f.id))`) using `countBlockingFindings` from `src/application/policy.ts`, guaranteeing real-time synchronization between UI badges and final exit code.
</threat_model>

  <action>
    1. Create `src/renderers/tui/state.ts` implementing the pure navigation and state machine:
       - Export `SEVERITY_ORDER: SeverityGroupKey[] = ['critical', 'high', 'medium', 'low', 'info']`.
       - Function `buildNavItems(findings: readonly RankedFinding[], expandedGroups: ReadonlySet<SeverityGroupKey>): NavItem[]`:
         - Loops through `SEVERITY_ORDER`.
         - Filters findings matching `groupKey`, sorted by `compositeScore` descending.
         - If count > 0: adds `{ type: 'header', groupKey, count, expanded: expandedGroups.has(groupKey) }`.
         - If `expandedGroups.has(groupKey)`: appends each finding as `{ type: 'finding', finding, groupKey }`.
         - Returns flattened `NavItem[]`.
       - Function `getActiveFinding(state: TuiState): RankedFinding | undefined`:
         - Computes `buildNavItems(state.findings, state.expandedGroups)`.
         - Returns `navItems[state.cursorIndex]?.type === 'finding' ? navItems[state.cursorIndex].finding : undefined`.
         - If cursor is on a header, returns the first visible finding following the header if available, or `undefined`.
       - Function `calculateActiveBlockingCount(state: TuiState): number`:
         - Computes `activeFindings = state.findings.filter(f => !state.suppressedIds.has(f.id))`.
         - Calls `countBlockingFindings(activeFindings, state.failOnSeverity)`.
       - Function `tuiStateReducer(state: TuiState, action: TuiAction): TuiState`:
         - `NAVIGATE_UP`: clamps `cursorIndex` to `Math.max(0, state.cursorIndex - 1)`, resets `evidenceIndex: 0`.
         - `NAVIGATE_DOWN`: clamps `cursorIndex` to `Math.min(Math.max(0, navItems.length - 1), state.cursorIndex + 1)`, resets `evidenceIndex: 0`.
         - `TOGGLE_GROUP_EXPAND`: if current item is `header`, toggles `groupKey` in `expandedGroups`.
         - `TOGGLE_SUPPRESSION`: if current item is `finding`, toggles `finding.id` in `suppressedIds`.
         - `TOGGLE_SNIPPET_MODE`: flips between `'source'` and `'diff'`.
         - `CYCLE_EVIDENCE`: cycles `evidenceIndex` through `0..N` where 0 is primary finding range and `1..N` are `finding.evidence` locations.
         - `OPEN_MODAL`: sets `activeModal` to `action.modal`, resets `explainScrollOffset: 0`.
         - `CLOSE_MODAL`: sets `activeModal: null`.
         - `SCROLL_EXPLAIN`: adjusts `explainScrollOffset = Math.max(0, state.explainScrollOffset + action.delta)`.
         - `SET_PROGRESS`: updates `progressEvent: action.event`.
         - `FINISH_REVIEW`: sets `findings = action.result.findings`, sets `viewMode = findings.length > 0 ? 'workspace' : 'clean'`, resets cursor.
         - `START_RE_REVIEW`: sets `viewMode: 'progress'`, `activeModal: null`.
         - Enter inspect / expand handling (TUI-02):
           - If active item is `{ type: 'header' }`: toggles group expansion (`TOGGLE_GROUP_EXPAND`).
           - If active item is `{ type: 'finding' }`: inspects the finding by opening the explanation overlay (`OPEN_MODAL` with `modal: 'explain'`), satisfying `Enter inspect`.

       - Test `TOGGLE_GROUP_EXPAND` toggles group expansion set.
       - Test Enter inspect / expand: verifies header toggles expansion and finding dispatches OPEN_MODAL with 'explain'.
       - Test `TOGGLE_SUPPRESSION` adds and removes finding IDs from `suppressedIds`.
